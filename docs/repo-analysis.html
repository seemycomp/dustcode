Đọc nhanh

Sản phẩm thực tế

Phạm vi phát hành là VS Code extension và backend local nhúng. Không nên suy luận rằng CLI, JetBrains hay các app upstream khác vẫn là sản phẩm Dustcode chỉ vì chúng còn trong cây mã nguồn.

Luồng chính

SolidJS webview gửi message tới extension host. Host dùng một connection service chung để gọi backend kilo serve qua HTTP/SSE.

Độ phức tạp

Phần khó nhất là session orchestration, tool loop, quyền/sandbox, event ordering và định tuyến project/session trong Agent Manager.

Ranh giới an toàn

Permission prompt và Git worktree không phải security sandbox đầy đủ. MCP, plugin, browser và provider vẫn là các vùng trust cần xem xét.

Phạm vi sản phẩm: README.md:3-24 và RELEASING.md:1-33 là nguồn chính cho nhận diện Dustcode, namespace dustcode.*, VSIX và CI không publish.

Quy trình xử lý prompt

  1. SDK gửi request tới typed Effect HTTP API.
  2. Session handler kiểm tra session và attachment.
  3. SessionPrompt dựng history, context, instructions và tool registry.
  4. SessionProcessor gọi model provider bằng stream.
  5. Tool call đi qua permission, sandbox, plugin hook hoặc MCP.
  6. Kết quả được đưa vào lượt model kế tiếp, hoặc session dừng/compaction/abort.
  7. Message, parts, events và persistence cập nhật; SSE chuyển dữ liệu tới webview.

Persistence và event

Code hiện tại dùng SQLite + Drizzle thông qua Effect. Database layer thiết lập WAL, busy timeout, foreign keys, migrations và channel-specific paths. Event layer cung cấp dữ liệu realtime cho SSE.

Database

packages/core/src/database/database.ts:16-75 là service layer hiện tại; packages/opencode/src/storage/db.ts:97-120 là client/migration path trong CLI.

Event stream

Handler SSE lọc theo directory/workspace và bridge các event envelope trước khi gửi tới client.

Documentation drift: một phần packages/opencode/AGENTS.md vẫn mô tả JSON filesystem và Hono theo kiến trúc cũ. Với session path đã khảo sát, source hiện tại dùng SQLite và Effect HttpApi. Khi phân tích route khác, hãy kiểm tra source thay vì áp dụng khái quát mù quáng.

Agent Manager

Agent Manager quản lý nhiều project, session, Git worktree, terminal, setup script và review/diff trong extension. Worktree được truyền vào backend dưới dạng directory qua shared client.

UI và hiệu năng diff

kilo-ui vừa là lớp component riêng vừa là adapter upstream. Button hiện re-export upstream component; CSS import upstream styles trước rồi thêm Kilo overrides và VS Code bridge.

Diff renderer dùng một IntersectionObserver dùng chung, deferred rendering và frame budget để tránh nhiều diff offscreen chặn chuyển session hoặc worktree.

Rủi ro cần nhớ

  1. Backend dùng chung: restart hoặc global state có thể ảnh hưởng nhiều UI/session.
  2. Routing bất đồng bộ: phải giữ project, generation và directory chính xác.
  3. SSE/webview ordering: cache, reconnect, remount và retry dễ gây race.
  4. Upstream coupling: component re-export và CSS import khiến dependency upgrade lan truyền.
  5. Diff lớn, nhiều worktree và Git polling cần đo hiệu năng trước khi đổi scheduling.
  6. Tài liệu kế thừa có thể stale; source và active CI là bằng chứng ưu tiên.
